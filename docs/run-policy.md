# Run safety and access policy

`POST /v1/runs`, capability invocation, and explicit validation accept `access_policy` with values `READ_ONLY` (default) and `READ_WRITE`. SQLite migration 0003 gives existing records `READ_ONLY`; every admitted run retains its policy independently of artifact provenance. Automatic internal validation inherits its source run's policy; explicit validation defaults independently to read-only. Changing the policy changes the idempotency request identity.

Both discovery and replay use the central decision boundary in `src/runtime/dispatch.ts` and `src/runtime/action-policy.ts`. Inspection tools read rendered state without generating input events. Runtime completion/intervention controls are allowed. All event-producing actions, including typing, selection, keys, scrolling and navigation away from the deployment entry URL, require trusted application rules. A rule may classify an action as `read` or `mutation`. Missing or conflicting rules yield `unknown`, which neither policy allows. Point interactions and global keys currently have no trusted target rule and fail closed. Native dialogs also fail closed: accepting or dismissing an unclassified dialog can resume mutation code, so the browser context is closed without either response.

Trusted rules are source-code configuration passed to `createBrowserFactory({ trustedActionRules })`, not fields of an API request, model tool, page annotation or saved artifact. Each rule has a stable ID, exact origin, pathname expression, tool action, target selector and category. Optional `accepts(action)` limits arguments such as key chords. Review the application's actual event handlers and focus/blur behavior before registering rules: an input labelled Search might autosave business data. Rules must remain valid across the whole supported UI state and deployment version. A current control handle is resolved, its frame and selector are checked, and the browser rechecks classification immediately before its input operation. This boundary assumes the integrated application code and rule configuration are trusted; it is not a sandbox for malicious page JavaScript.

There are no production application interaction rules in this change. The default runner therefore fails closed on such interactions under either policy. Local fixtures supply explicit trusted rules for read-only search/profile retrieval and a server-counted mutation. Do not copy broad test-fixture rules into production. Add reviewed integration rules to the code-owned factory configuration before enabling real workflows.

The hostname derives from the deployment's immutable base URL snapshot, not the artifact entry URL. The gate uses URL hostname equality: subdomains and lookalike suffixes differ; scheme and port changes do not alter the hostname (HTTP/S only). Context routing blocks foreign document requests and all unsupported popup document requests. Chromium CDP Fetch interception checks every redirect hop for the supported page and its frames. External scripts/images remain permitted. Networkless foreign documents cause a terminal breach; transient empty child frames are allowed. Policy runs disable service workers to prevent request interception bypass. This is a document-navigation restriction, not an egress firewall for application API traffic.

A policy rejection includes effective policy, category, reason, violation code and dispatch state in the canonical `tool_finished` result. The preceding `tool_started` retains the rejected action. Asynchronous browser breaches additionally emit `policy_violation`. A direct rejected action is `not_dispatched`; navigation discovered during a dispatched link or redirect chain is `uncertain` for that initiating action, even though the foreign request is blocked. Pending model work is aborted on domain breach. Terminal processing closes the browser before choosing the final result, preventing a late navigation from becoming a success or business outcome. Discovery never publishes an artifact after a breach. `violationResponse` is the future outcome-extension point; no operator surface or transfer workflow is implemented.

Verification uses real local Chromium and synthetic HTTP counters: no foreign document requests, external asset loading, default read-only search/profile extraction, unknown Search-labelled effects, autosave prevention, identical known mutation denied under read-only and executed under read-write, replay enforcement, asynchronous navigation during model/audit waits, popup redirects and child frames. Backend tests cover request validation/idempotency, persisted policy, migration/backup, bridge propagation, exact error codes, and artifact suppression. The Python-to-Node integration confirms an existing artifact cannot authorize unclassified interactions under either policy. No production deployment or paid/live discovery was performed.
